## 结论

- 宿主机 `--mode both` 一条命令产出 ladder + soak 单份报告，**8 项门槛全部通过**（`docs/evals/soak-20260915-host.json`）。

## 复现命令

```bash
rm -rf /tmp/pb-soak
.venv/bin/brain --db /tmp/pb-soak/soak.sqlite --archive-dir /tmp/pb-soak/archives \
  soak --mode both --conversations 500 --messages 200 --seed 20250801 \
  --levels 1,2,4,8 --warmup-seconds 30 --queries-per-level 5000 \
  --concurrency 4 --duration 1800 --total-queries 50000 --rss-interval 5 \
  --rss-baseline-after 30 --out docs/evals/soak-20260915-host.json
```

## 加分项：并发写（writer 模式，单独披露）

`--mode soak --writer`：读侧并发 4 不变，另起 1 个写进程每 15s 导入 1×20 条同 ID 新版本
（WAL，`synchronous=FULL`）。运行 601s（`soak-20260915-host-writer.json`）：

- 写侧：40 批次，新增 800 revisions（events/sources 不变 100,000），增量与读侧报告完全一致
  （`writer_growth_consistent` ✓），0 失败；完整性 ok ✓。
- 读侧：3,181 次查询，QPS 5.294（无写侧时 9.894），P95 2122.8ms，0 错误；
  **漂移比 4.4114 > 1.3，门槛未过**（前 10% P95 213.8ms → 末 10% 943.1ms）。
- 解读：小批次持续写入与读侧在同一 WAL 上竞争，读侧延迟显著抬升且随写侧推进而恶化。
  这是写入并发的真实代价，如实披露；主 soak（纯读）不受影响。改进方向（后续任务）：
  降低 checkpoint 频率、读写分库或 `busy_timeout`/retry 调参后再评估。

## 容器缩短口径冒烟（soak-docker-smoke.json，非全量、不与宿主机全量对比）

命令（compose 覆盖参数）：

```bash
docker compose run --rm soak --db /tmp/pb/soak.sqlite --archive-dir /tmp/pb/archives \
  soak --conversations 500 --messages 200 --mode both --levels 1,4 \
  --queries-per-level 500 --warmup-seconds 10 --duration 300 \
  --total-queries 3000 --rss-baseline-after 10 --out /out/soak-docker-smoke.json
```

结果（Ubuntu 24.04 VM / SQLite 3.46.1 / 8 vCPU，100k 语料）：ladder c1 P95 833.8ms、
c4 P95 1861.6ms（各 500 次）；soak 5 分钟 1319 次，QPS 4.383，P95 1545.8ms，错误 0；
漂移比 1.5534；RSS 增长 1.0；`integrity_check=ok`，行数导入前后一致。

如实披露：缩短口径下两项门槛未过——`ladder_c4_warm_p95_le_1000ms`（1861.6ms）与
`soak_drift_ratio_le_1_3`（1.5534）。样本量小（500 次/档、5 分钟窗口）本身放大噪声，
且容器并发读明显慢于宿主机（c1 P95 833.8ms vs 宿主 471.1ms），全量口径未复跑、
不据此下结论；完整复现命令见 `docker-reproducibility.md` 第 6 节。RSS 与完整性两项
长稳关键指标在容器内同样平稳（增长比 1.0、integrity ok）。
